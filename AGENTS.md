## Authority map

- The framework's documents are described in the [agent orientation](governance/AGENT-ORIENTATION.md) and indexed in [governance/](governance/README.md). This map covers the project's own documents.
- [project-governance/](project-governance/CONSTRAINTS.md) holds the project's own rules ([Constraints](project-governance/CONSTRAINTS.md)) and decisions ([Decisions](project-governance/DECISIONS.md), with their [rationale](project-governance/RATIONALE.md)); they add to the framework's and never override them.
- `docs/` holds domain/product designs, architecture, plans, current progress and component evidence. [ARCHITECTURE](docs/ARCHITECTURE.md) describes the current architecture.
- Relevant component specifications and contracts define normative behavior. Frozen specifications/contracts outrank implementation convenience; implementations adapt to them. Report conflicts rather than silently changing frozen artifacts.
- [PLAN](docs/PLAN.md) holds the long-term direction and [PROGRESS](docs/PROGRESS.md) the verified current state, with no task lists.
- [devlog/](devlog/README.md) holds the project's historical records: human-oriented and non-normative.
